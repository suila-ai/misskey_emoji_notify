# misskey_emoji_notify

Misskey のカスタム絵文字の変更を知らせる bot。

- 絵文字の一覧を 10 分ごとに確かめ、追加・削除・名前の変更・画像の変更・カテゴリの変更・タグの変更をノートで知らせる。
- 全絵文字を並べた画像を作ってプロフィールのバナーにする。絵文字が増減したり画像が変わったりしてバナーが一覧と合わなくなったら、作り直す。手でバナーを差し替えても、次の確認で bot のバナーに戻す。手で外したり差し替えたりしたときは、それまでの bot のバナーのファイルがドライブに残る。絵文字が 1 つも無くなったら、bot のバナーを外す。
- 前日のローカルタイムラインのリアクションを集計し、毎日決まった時刻（既定は 0 時）にランキングを投稿する。その時刻に止まっていたら、同じ日のうちに起動したときに投稿する。ほかの人のノートへの返信は集計に含めない。数えるのはこのサーバの絵文字と Unicode の絵文字で、どちらのリアクションも無い日は投稿しない。
- メンションに応答する。「ガチャ [個数] [カテゴリ...]」で絵文字をランダムに引き、「占」「うらな」「運勢」「おみくじ」のどれかを含むメンションにはその日の運勢を返す。「ガチャ」は「gacha」でもよく、一度に 50 個まで引ける。呼び出しは本文と CW のどちらに書いてもよい。起動してからストリーミングにつながるまでの間と、切れていた間のメンションにも、つながったあとに応答する。ただし、30 分より古いものには応答しない。

初回（控えが無いとき）は絵文字の一覧を控えるだけで、何も投稿しない。2 回目からは前回の控えと比べて差分を知らせる。サーバが空の一覧を返したときは、不調のこともあるので 1 回目は差分を取らずに見送り、2 回続いたら全部の削除として知らせる。画像は URL ではなく中身（SHA-1）で比べるので、URL を変えずにリダイレクト先で差し替えた画像も検知する。

## 使い方

Docker と Docker Compose を使う。

1. `config.example.toml` を `config.toml` に写し、Misskey のサーバとアクセストークン（`read:account`・`write:account`・`read:drive`・`write:drive`・`write:notes`・`write:reactions`）を書く。使わない機能はその節ごと消す。bot はコンテナの中で uid 65532 として動くので、`config.toml` はその uid から読める権限にしておく（自分だけが読める 600 にすると、Permission denied で起動に失敗し続ける）。
2. `docker compose up -d --build` で起動する。ログは `docker compose logs -f` で見る。
3. 設定を変えたら `docker compose restart` で読み直す。コードを更新したら `docker compose up -d --build` で作り直す。

絵文字の控えと画像は名前付きボリューム `state` に残る。

Misskey は 2025.10.0 から 2026.5.0 までのサーバを相手にできる。

## 開発

```sh
cargo fmt --all --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
```

ローカルの Misskey に向けて動かすには、`scripts/misskey/up.sh` で使い捨てのサーバを立て、表示される手順に従う。bot のアカウントとカスタム絵文字を作り、接続情報を `scripts/misskey/.env.local` に書く。管理者のトークンで `admin/emoji/update` などを呼ぶと、bot の通知を確かめられる。`scripts/misskey/down.sh` でデータごと消える。
